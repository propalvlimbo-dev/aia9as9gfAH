# ElytrixAuth + ElytrixBot

Авторизация для Minecraft-сети на прокси (**NullCordX / Waterfall / BungeeCord**)
с привязкой аккаунтов к Telegram и входом по паролю + подтверждением в Telegram (2FA).

```
Капча NullCordX → auth-сервер (маленькая карта) → /reg или /login
                                                   │
      аккаунт привязан к TG ──┘ пароль верный ──→ 2FA вкл: кнопка «Войти» в боте
                                                  2FA выкл: бот шлёт уведомление о входе
                                                   │
                                                   ▼
                                            target-сервер (grief)
```

## Состав

| Часть | Путь | Что делает |
|---|---|---|
| Плагин | `elytrixauth-plugin/dist/ElytrixAuth.jar` | Java (Bungee API): команды `/reg /register /login /l /logout /addtg`, админ-команды `/elytrixauth` (`/ea`), удержание неавторизованных на auth, 2FA (вкл/выкл per-аккаунт), уведомления о входах в TG (вкл/выкл), заморозка аккаунта, история входов, кик/смена пароля через HTTP API (со сбросом сессии и киком), защита от перебора |
| Бот | `elytrix-bot/` | Python (aiogram 3): `/link <код>`, `/menu` — reply-клавиатура-меню (главная + разделы 🛡️ Безопасность / 🎮 Игровой процесс / 🎁 Награды), inline «Войти / Отклонить» и уведомления о входах с кнопкой «Кикнуть» |
| БД | **встроена в плагин** (HSQLDB embedded) | файл БД в `plugins/ElytrixAuth/db/`, таблицы создаются сами при старте, ничего устанавливать не нужно |
| Мост | `elytrixauth-bridge/dist/ElytrixAuthBridge.jar` | Маленький Bukkit-плагин для игрового сервера (`grief`): по plugin messaging отдаёт прокси префикс/группу LuckPerms и коины PlayerPoints (оба - Bukkit-плагины, с прокси до них напрямую не достучаться) |

Бот **не ходит в БД**: он общается с плагином по встроенному HTTP API
(бот «кидает запросы и получает ответы»), поэтому базу наружу открывать не нужно.

## 1. База данных — встроена, ничего делать не нужно

Плагин использует **HSQLDB** (полноценную SQL-БД) во встроенном режиме:
- файл БД — `plugins/ElytrixAuth/db/elytrix.*`;
- таблицы `players`, `pending_links`, `login_requests` создаются автоматически при первом запуске;
- **не нужно ставить MariaDB/MySQL/Postgres, заводить юзеров и пароли БД, открывать порты**.

## 2. Плагин (в plugins/ NullCordX)

1. Положить `elytrixauth-plugin/dist/ElytrixAuth.jar` в папку `plugins/` прокси.
2. Перезапустить NullCordX → создастся папка `plugins/ElytrixAuth/` с
   `config.properties` и `messages.yml` (и в `db/` — файл встроенной БД).
3. Проверить в `config.properties`: `auth.server` (имя auth-сервера из config.yml прокси)
   и `target.server` (куда переводить после входа, у тебя `grief`). Пароли/БД настраивать **не нужно**.
4. Если `api.secret` пуст — он сгенерируется сам, значение напечатается в консоль
   (нужно для бота). Перезапустить прокси ещё раз.

### messages.yml — все сообщения плагина

Все тексты (приветствия, подсказки, ошибки, кики, боссбар) лежат в
`plugins/ElytrixAuth/messages.yml`. Цвета: `&c`, градиенты — `&#RRGGBB`,
`{prefix}` подставляет префикс `☁ ᴇʟʏᴛʀɪx`. Правишь файл → перезапуск прокси.

### Что видит игрок при входе (UI)

- **Title по центру экрана**: «Регистрация» (если аккаунта нет в базе) или «Вход» —
  понятно даже при выключенном чате;
- **Actionbar** над хотбаром: что вводить — `/reg <пароль> <пароль>` или `/login <пароль>`;
- **Пурпурный bossbar с таймером**: сколько секунд осталось на авторизацию;
  время вышло → кик с подсказкой;
- **Таб** у неавторизованного показывает только нужную команду —
  регистрирующемуся `/register` (`/reg`), входящему `/login` (`/l`);
  список серверных команд и ники игроков не светятся; после пробела таб
  подставляет слово-заглушку `ПАРОЛЬ` (`/l<tab> → /l <tab> → /l ПАРОЛЬ`);
- на игровом сервере `/login`, `/l`, `/register`, `/reg` не работают
  (молча гасятся и не показываются в табе) — они только для входа на auth;
- **после `/reg` или `/login`** в title идёт короткая декоративная анимация
  «Проверка пароля» (ничего не проверяет — просто красивый ход), затем
  финальный «успех» и перевод на игровой сервер;
- команды и чат до входа заблокированы, подсказка зависит от ситуации:
  новичку пишем «зарегистрируйся», а не «введи /l».

### Сессии (вход без пароля после перезахода)

Если игрок вышел и зашёл снова в течение срока сессии **с того же IP** —
пароль не спрашиваем, пускаем сразу. Проверки строгие:

| Ключ в config.properties | По умолчанию | Что делает |
|---|---|---|
| `sessions.enabled` | `true` | вкл/выкл сессии |
| `session.max.seconds` | `21600` (6 ч) | срок жизни сессии |
| `session.check.ip` | `true` | сессия привязана к IP: **с другого IP сессия сбрасывается** и спрашивается пароль |

Сессия выдаётся при `/reg` и при успешном `/login`. Смена IP → пароль заново
(игроку показывается «сессия сброшена»).

Обязательные настройки прокси/бэкенда (уже сделаны у тебя):
- NullCordX: `online_mode: false`, `forwarding_mode` + совпадающий секрет;
- auth и все бэкенды: `server.properties → online-mode=false`,
  Paper: `velocity-support` или `spigot.yml → bungeecord: true` — **один режим**,
  совпадающий с `forwarding_mode` NullCordX;
- `priorities: [auth]`, `force_default_server: true` — все сначала попадают на auth.

### Команды

| Команда | Действие |
|---|---|
| `/reg <пароль> <пароль>` (`/register`) | регистрация (только на auth, пока не авторизован); если у аккаунта нет пароля (админ сбросил) — создаёт новый |
| `/login <пароль>` (`/l`) | вход; если аккаунт привязан к TG и у него **включена 2FA** — после пароля бот присылает кнопку «Войти / Отклонить»; если 2FA выключена (по умолчанию) — бот присылает уведомление о входе (ник, IP, время) |
| `/addtg` | получить код привязки Telegram (работает на любом сервере сети): короткая инструкция в чате с кликабельными `/link <код>` (клик копирует) и `@Elytrixbot` (открывает бота); над хотбаром — код с отсчётом до удаления (срок в чате не пишется). `/addtg cancel` — отменить код и убрать отсчёт. Код 6-значный, живёт 5 минут, повторный `/addtg` новый код не выдаёт, пока старый жив |
| `/logout` | выйти с аккаунта: сессия стирается, игрока кикает, следующий вход — снова `/login` |

Пока игрок не авторизован, title по центру экрана («Регистрация» / «Вход» /
«Подтверди вход в Telegram») не исчезает — плагин повторяет его каждые 5 секунд.

### Админ-команды (`/elytrixauth`, алиас `/ea` — **только из консоли прокси**, с игры недоступны)

| Команда | Действие |
|---|---|
| `/elytrixauth reload` (`rl`) | перезагрузить `config.properties`, `messages.yml`, БД и HTTP API без перезапуска прокси |
| `/elytrixauth reset <ник>` | полный сброс аккаунта: пароль, привязка Telegram, сессия. Требует подтверждения (повторить команду в течение 15 сек). Если игрок онлайн — его кикает; при следующем входе он создаёт новый пароль через `/reg` |
| `/elytrixauth resetpassword <ник>` (`resetpass`) | сброс только пароля (Telegram-привязка сохраняется), с подтверждением |

### Как это защищено

- Пароли: **PBKDF2-HMAC-SHA256**, 210 000 итераций, соль 16 байт (не сырой SHA-256);
- лимит неверных `/login` (по IP и нику) → кик, чтобы не перебирали;
- таймер на авторизацию (по умолчанию 180 сек) → кик;
- неавторизованный не может сменить сервер (`/server`, реконнекты) — все дороги ведут на auth;
- страховка: если неавторизованный каким-то образом оказался на игровом сервере
  (гонка, сторонний плагин-редирект) — плагин сразу кикает его с «Пройди авторизацию»;
  прямое подключение к бэкенду в обход прокси отсекает сам forwarding прокси
  (на бэкендах включён `bungeecord: true` / velocity-режим);
- чат и команды (кроме `/reg /login /addtg`) заблокированы до входа;
- код привязки одноразовый, 6 цифр, живёт 300 сек, проверка коллизий, `/addtg cancel` отменяет его;
- 2FA (кнопка подтверждения входа в Telegram) **по умолчанию выключена**: привязанный аккаунт
  входит сразу, бот шлёт уведомление о входе (ник, IP, время). Включается/выключается в боте
  (панель управления, кнопка «Включить/Выключить 2FA»). При включённой 2FA вход без кнопки
  невозможен (авто-сессия не действует), 2FA-запрос живёт 90 сек и обрабатывается один раз;
- смена пароля через бота применяет те же правила, что и `/reg` (мин. длина из
  `min.password.length`, не совпадать с ником, не из одинаковых символов), сессия сбрасывается;
- кик через бота дополнительно сбрасывает сессию — следующий вход будет по паролю;
- «ошибка сетевого протокола» после регистрации/киков лечится так: все кики плагина
  (кроме явного входа) отложены на 200–500 мс, чтобы клиент штатно закрыл поток
  (актуально для 1.20.2+, где LoginSuccess приходит только после коннекта к серверу,
  и для агрессивных VPN); после `/reg` перевод на игровой сервер дополнительно
  сдвинут на ~3.5 сек (анимация + пауза), а повторяющийся actionbar с одинаковым
  текстом больше не шлётся каждую секунду.

### Защита от ботов и перебора (config.properties)

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `ban.ip.after.tries` | `3` | после 3 неверных входов с одного IP за окно — IP банится (бан переживает рестарт прокси, хранится в БД) |
| `ban.ip.minutes` | `30` | длительность бана IP; забаненный не зайдёт, даже если у него была сессия |
| `reg.max.per.ip` | `3` | с одного IP можно зарегистрировать не больше 3 аккаунтов (четвёртый `/reg` отклоняется) |
| `online.max.per.ip` | `3` | одновременно с одного IP может играть не больше 3 аккаунтов — четвёртого кикает при входе (анти-мультибокс) |
| `min.password.length` | `4` | мин. длина пароля при `/reg` |
| `max.failed.tries` / `failed.window.seconds` | `5` / `60` | лимит неверных попыток (по нику) до кика за окно |

`/reg` также отклоняет слишком простые пароли: пароль, совпадающий с ником,
и пароль из одинаковых символов (`aaaaaa`, `111111`). Ключи защиты `ban.*`, `reg.max.per.ip`
и `online.max.per.ip` можно выключить значением `0`.

## 3. Бот (Python, хостинг/Pterodactyl)

```bash
cd elytrix-bot
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env   # заполнить BOT_TOKEN, API_BASE, API_KEY
.venv/bin/python main.py
```

На Pterodactyl: egg `Python`, стартовая команда `python main.py`, переменные —
в разделе Environment: `BOT_TOKEN` (от @BotFather), `API_BASE=http://IP_ТВОЕГО_VDS:8754`
и `API_KEY` — **тот же, что `api.secret` в `config.properties` плагина**
(его печатает плагин в консоль при старте), и `CHANNEL_ID=@elytrix_ru`
(канал для «Награды и бонусы»; бота добавь в канал **администратором**,
иначе Telegram не разрешит проверять подписку; пустое значение = проверка выключена).

Внешний доступ к боту **не нужен**: он сам ходит в Telegram (long-polling) и к HTTP API плагина.
В firewall VDS открой порт `8754` хотя бы для IP хостинга бота:
```bash
ufw allow from <IP_ХОСТИНГА_БОТА> to any port 8754 proto tcp
```

### Пользовательский сценарий

1. Игрок в игре: `/addtg` -> плагин показывает 6-значный код (с отсчётом над хотбаром).
2. Игрок в Telegram боту: `/link 123456` -> «Аккаунт привязан», и внизу чата
   появляется **главная страница панели - reply-клавиатура** (видна всегда,
   пока бот не уберёт её). Кнопки сгруппированы по 2 в ряд. Разделы (папки):

   **🛡️ Безопасность** (2 колонки)
   - 🔑 Сменить пароль / ⛏ Кикнуть;
   - 🔐 Включить 2FA / 🔓 Выключить 2FA / 🚪 Все сессии;
   - 📜 История входов / 🧊 Заморозить / 🔥 Разморозить;
   - 🔔 Включить увед. / 🔕 Выключить увед. / ⬅️ Главная.

   Подробности:
   - 🔑 **Сменить пароль** - новый пароль сообщением; старый и **все сессии**
     теряют силу, игрока **кикает с сервера**, если он онлайн;
   - 🔐/🔓 **2FA** - по умолчанию выключена: при входе только уведомление;
     включена - кнопки **✅ Войти / ❌ Отклонить** в боте;
   - ⛏ **Кикнуть** - кик + сброс сессии (то же делает inline-кнопка под уведомлением о входе);
   - 🚪 **Все сессии** - вывести из игры и сбросить сессии;
   - 📜 **История входов** - последние 10 входов (IP + время);
   - 🧊 **Заморозить / 🔥 Разморозить** - экстренный запрет входа в 1 клик
     (заморозка сразу выгоняет игрока, если онлайн);
   - 🔔/🔕 **Уведомления** - вкл/выкл оповещений о входе в игру в ТГ.

   **🎮 Игровой процесс** (2 колонки)
   - 👤 Профиль / ⚖️ Наказания;
   - 🎉 Ивенты / 🆘 Поддержка;
   - 📋 Правила / ⬅️ Главная.

   - 👤 **Профиль и статистика** - реальные данные (см. ниже «Донат и коины»):
     донат-префикс и группа LuckPerms, коины PlayerPoints, наигранное время;
     данные кэшируются на 10 минут и прогреваются при заходе игрока на сервер;
   - 🎉 **Активные ивенты** - заглушка; проверяется привилегия **Elder**
     (primary-группа LuckPerms, список в `elder.groups`);
   - ⚖️ **Наказания** - заглушка (подключится свой плагин наказаний);
   - 🆘 **Поддержка** - @Elytrix_Help;
   - 📋 **Правила** - кнопка со ссылкой на elytrix.pw.

   **🎁 Награды и бонусы**
   - 🎁 Дневной бонус / 🏷️ Промокоды - заглушки (заработают с ElytrixFree);
   - 📢 Канал Elytrix / ⬅️ Главная.

   Раздел «Награды» **закрыт по умолчанию**: откроется только после проверки
   подписки на канал `@elytrix_ru` (кнопка «Я подписался» перепроверяет).
   Бот должен быть добавлен в канал **администратором**, в .env задан
   `CHANNEL_ID`; если проверка не удалась/не настроена - раздел остаётся закрыт.

3. Отвязка: `/unlink` в боте (вручную, через администратора).

Уведомления о входах (2FA выключена) приходят отдельным сообщением вида
«🔓 Вход в аккаунт „Ник“ · IP · время» - **под ним сразу кнопка «⛏ Кикнуть»**
(inline прямо в сообщении): кикнет игрока с сервера и сбросит его сессию.

**Один Telegram - один аккаунт:** повторно привязать второй аккаунт к тому же
Telegram нельзя (и в боте, и в игре `/addtg` сразу об этом напишет).

### Донат и коины (профиль): LuckPerms + PlayerPoints + мост

LuckPerms умеет работать на самом прокси - его плагин опрашивает напрямую
(рефлексия, без сборки против LP). PlayerPoints - **только Bukkit-плагин**,
поэтому префикс/группа/коины с игрового сервера получаются по plugin messaging:

1. Положи `elytrixauth-bridge/dist/ElytrixAuthBridge.jar` в `plugins/` игрового
   сервера (`target.server`, у тебя `grief`) и перезапусти его.
2. Всё. Прокси сам шлёт запрос через любого онлайн-игрока на том сервере
   (канал `elytrix:auth`), мост отвечает данными LuckPerms/PlayerPoints.

Что увидишь:
- 👤 Профиль -> «Донат (LuckPerms): <префикс> (группа: <группа>)» и
  «Коины (PlayerPoints): <баланс>»;
- 🎉 Активные ивенты -> проверка Elder работает и когда LP стоит только
  на игровом сервере (не на прокси).

Если плагинов нет / мост не стоит / на игровом сервере никого нет онлайн -
бот аккуратно напишет «не удалось получить» вместо ошибки.

## 4. Сборка плагина из исходников

```bash
cd elytrixauth-plugin
# hsqldb.jar (встроенная БД) уже в lib/. Если его нет — скачай HSQLDB
# (jar org.hsqldb:hsqldb) и положи в lib/hsqldb.jar.
./build.sh          # нужен JDK 17+; JAVAC=... ./build.sh, если javac не в PATH
# результат: dist/ElytrixAuth.jar (HSQLDB вшита внутрь)
```

Стабы Bungee API в `elytrixauth-plugin/stubs/` нужны только для компиляции
(в рантайме API даёт сам прокси), поэтому собирать можно без интернета.

## Известные ограничения v1

- 2FA привязан только к Telegram; VK/Discord/Google Authenticator не поддерживаются.
- Бот не может подтверждать вход, если игрок не написал боту хотя бы раз
  (Telegram не даёт писать первым) — это штатное ограничение Telegram.
- Кик снимает игрока с сервера только в момент нажатия: если он офлайн,
  кик не «сработает сам» при следующем входе (но сессия сброшена — вход будет по паролю).
